# VibeHub 商业产品计划

> 版本：v2.0 · 2026 年 9 月 · 面向 AI Native 研发团队的「双端同步研发上下文总线」
> 本文档覆盖：商业定位与收入模式、账户体系（登录/组织/权限）、MCP 密钥体系、数据模型演进、2026 主题 UI 设计规范（以白泽观智设计语言为基底）、技术路线图、GTM 与风险。

---

## 0. 一页概览

**产品**：VibeHub = 给人用的极简研发看板 + 给 AI 用的 MCP 上下文服务。测试/产品在 Web 端粘贴截图即录缺陷，IDE Agent（Cursor / Windsurf / Claude Code）通过 MCP 直接读取复现步骤、截图与日志，修复后回填状态，看板实时同步。

**商业形态**：Open-Core。核心引擎开源（自托管永久免费完整可用），在此之上提供云托管与团队/企业服务形成收入。

**收入来源**：

| 来源 | 形态 | 说明 |
| --- | --- | --- |
| 云托管订阅 | 按席位月付/年付 | 免运维、自动备份、团队协作与治理能力 |
| 集中式 MCP 节点 | 订阅制，按调用计量 | 内网统一端点，成员免本地配置 |
| Enterprise 服务 | 年度合约 + 实施费 | 私有化部署、SSO、SLA、专属支持 |
| 生态 | 模板与集成分成 | 模板市场、高级集成按抽成 |

**北极星指标**：每周通过 MCP 被 AI 消费的缺陷上下文条目数（`context_consumed/week`）。
**激活指标**：新用户 10 分钟内完成「粘贴第一张截图 → 生成缺陷」的比例，目标 ≥ 60%。

## 1. 市场机会与定位

### 1.1 背景

- AI Coding 工具进入普及期，Cursor、Windsurf、Claude Code 等已重塑写代码的方式，但**上下文供给方式没有升级**：缺陷仍记录在 Jira/Tapd/飞书，开发者手动复制粘贴给 AI，截图被防盗链拦截，日志一贴就撑爆上下文窗口。
- MCP（Model Context Protocol）成为 IDE Agent 连接外部工具的事实标准，**先占位「研发工单 × MCP」这一垂直场景的团队将获得分发优势**。
- 目标客群清晰且付费意愿强：已在为 Cursor 席位付费的团队，对「让 AI 真正看懂 bug」有直接 ROI 感知（减少来回澄清轮次）。

### 1.2 竞争格局与差异化

| 竞品 | 形态 | 短板 | VibeHub 差异 |
| --- | --- | --- | --- |
| Jira / Tapd / 飞书项目 | 传统工单 | 附件无 AI 适配接口、录入重、无 MCP | 截图即录 + MCP 原生 |
| Linear | 现代工单 | 同样无 AI 通道 | 双端总线定位 |
| Context7 / MCP 目录 | 文档类 MCP | 只读文档，非业务流数据 | 业务流数据闭环（录入→消费→回填） |
| 自建脚本 | 散装 | 无看板、无审计、无密钥管理 | 产品化 + 可商业化 |

### 1.3 定位声明

> VibeHub 是 AI Native 研发团队的**上下文总线**：人类用最懒的方式录入（粘贴），AI 用最省的方式消费（分片与降采样），状态双向同步。

## 2. 商业模式

### 2.1 收入结构

```
                ┌─────────────────────────────────┐
   基础盘 ────► │ 云托管订阅（按席位）              │
                ├─────────────────────────────────┤
   增长盘 ────► │ 集中式 MCP 节点（订阅 + 按调用计量）│
                ├─────────────────────────────────┤
   高客单 ────► │ Enterprise 年度合约（私有化 + 服务）│
                ├─────────────────────────────────┤
   生态盘 ────► │ 模板市场 / 高级集成分成            │
                └─────────────────────────────────┘
```

设计原则：

- **核心能力永久免费**：自托管版功能完整（Open-Core 边界见 §7.3），云服务只卖便利与协作治理，不靠裁剪功能逼升级。
- **按席位而非按功能点收费**：团队为「人」付费，管理后台可随时调整席位数。
- **计量透明**：所有消费行为（MCP 调用、存储、席位）可在后台实时查询，账单可解释。

### 2.2 计费指标（Metering）

所有计量事件写入 `usage_events` 表，按天聚合、按月出账：

- `mcp.tool_call`（按 key、按工具名）
- `attachment.storage_gb_day`
- `seat.active_day`
- `api.request`

配额（速率限制、存储上限、调用总量）由管理后台按部署/组织统一配置，管理员可在控制台自助调整。

## 3. 账户体系与登录（商业化地基）

### 3.1 注册与登录

**登录页（设计见 §6.5）**支持多种凭据方式，按部署需要启用：

| 方式 | 说明 |
| --- | --- |
| 邮箱 + 密码 | argon2id 哈希，密码强度策略，防撞库 |
| 邮箱魔法链接 | 15 分钟有效、一次性、防枚举 |
| GitHub / Google OAuth | 一键授权即注册，GitHub 优先（开发者密度最高） |
| 短信验证码 | 滑块验证码前置，60s 重发（面向国内团队部署启用） |
| OIDC / SAML SSO | 企业 IdP 接入（飞书、钉钉、Okta、Azure AD），企业版提供 |

**安全基线**：
- 会话：access token（15 分钟，JWT）+ refresh token 轮换（30 天，一次性使用，检测重放即全族吊销）
- 设备管理：用户可查看登录设备列表并远程登出
- 2FA：TOTP，用户可开启，组织管理员可强制
- 防护：登录/发信/密钥创建按 IP+账号双维度限速；异地登录邮件告警
- 登录审计：每次认证记录 IP、UA、结果，进入 `audit_logs`

### 3.2 组织模型（多租户）

```
User（用户）
 └─ Membership ─ Organization（组织/团队）
      └─ Workspace（= 现有 Project，升级为组织内命名空间）
           ├─ Role: Owner / Admin / Member / Viewer
           └─ AI Agent（虚拟成员：持有 MCP 密钥，可被授予 Viewer+）
```

- **租户隔离**：所有业务表增加 `org_id`；PostgreSQL 阶段启用 Row-Level Security，按 `app.current_org` 隔离，杜绝跨租户串数据。
- **邀请流**：邮件/链接邀请（7 天有效、可撤销、可限域名自动加入，企业版）。
- **项目 slug 唯一性**改为组织内唯一（`@@unique([org_id, slug])`），保持「AI 按仓库名自动匹配」的产品心智。

### 3.3 RBAC 矩阵

| 操作 | Owner | Admin | Member | Viewer |
| --- | :-: | :-: | :-: | :-: |
| 创建/删除项目 | ✓ | ✓ | ✗ | ✗ |
| 录入/编辑缺陷、便签 | ✓ | ✓ | ✓ | ✗ |
| 拖拽改状态 | ✓ | ✓ | ✓ | ✗ |
| 上传附件 / 删除他人附件 | ✓ | ✓ | ✓ / ✗ | ✗ |
| 创建 MCP 密钥 | ✓ | ✓ | ✗ | ✗ |
| 撤销任意密钥 | ✓ | ✓ | ✗ | ✗ |
| 查看审计日志 | ✓ | ✓ | ✗ | ✗ |
| 组织与计费设置 | ✓ | ✗ | ✗ | ✗ |

> 现状（MVP）的 `created_by: 'human' | 'ai'` 字段将升级为 `creator_id`（可指向 User 或 API Key），保留「AI 创建」徽章的展示语义。

## 4. MCP 密钥体系（核心商业控制点）

MCP 是 AI 消费 VibeHub 的唯一入口，**密钥即 API Key，是计量单元、权限载体与审计锚点**。

### 4.1 密钥模型

```
vhk_live_7Kd9xQ2mR4pL8sT1wY6zB3nF5jH0cV   （前缀可辨环境）
vhk_test_...                                （沙箱：读写隔离数据）
```

- **存储**：仅存 SHA-256(密钥 + 每密钥随机 salt)；明文只在创建成功响应中出现一次，之后不可找回（丢失只能轮换）。
- **元数据**：名称、作用域、绑定项目、创建者、创建时间、最后使用时间、过期时间、撤销状态。
- **展示**：列表页只显示掩码 `vhk_live_7Kd9••••••••5jH0cV`，悬停显示创建者与最近使用。

### 4.2 作用域（Scopes）

| Scope | 允许的工具 |
| --- | --- |
| `context:read` | get_project_context、list_bugs、get_bug_detail |
| `attachment:read` | read_attachment_text、inspect_image_asset |
| `bug:write` | update_bug_status |
| `note:write` | append_scratchpad |
| `admin` | 全部 + 密钥管理 |

最小权限默认：创建密钥时默认勾选 `context:read`，写操作需显式勾选（防 AI 误改状态，即设计文档的「防脏写」在密钥层的延伸）。

### 4.3 生命周期

```
创建（一次性明文）→ 使用（计量 + 审计）→ 轮换（新旧双活 24h 重叠期）→ 撤销（立即失效）
                                    ↘ 过期（TTL，可配置，默认 90 天）
```

- **轮换**：一键轮换生成新密钥，旧密钥进入 24 小时宽限期（供 IDE 配置切换），超时自动失效。
- **撤销**：Owner/Admin 可撤销组织内任意密钥；用户怀疑泄漏时可自助「一键撤销并轮换」。
- **告警**：密钥首次在新 IP/网段使用、调用速率突增 10 倍、非工作时段批量调用 → 邮件/Webhook 告警。

### 4.4 配额与限流

- 每密钥：QPM 限制（按部署配置），超限返回 429 + `Retry-After`，MCP 层转为友好的 `isError` 结果而非崩溃。
- 每组织：月度 `mcp.tool_call` 总量上限由管理员配置，达到软限制时醒目提示而非硬断。
- 附件总量：存储配额管理后台可调，超限禁止上传但保留读取。

### 4.5 MCP 节点形态（密钥的应用场景）

| 形态 | 说明 |
| --- | --- |
| 本地 stdio 节点 | IDE 以子进程拉起 `mcp-entry.ts`，直连本地/自托管数据库，个人与自托管部署默认形态 |
| 团队 SSE 节点 | 内网统一端点 `https://mcp.<org>.vibehub.dev/sse`，密钥即 Bearer Token，成员免本地配置 |
| 托管云节点 | VibeHub 运维的集中节点，多租户隔离，按调用计量 |

> 团队 SSE 节点复用现有 `@modelcontextprotocol/sdk` 的 SSEServerTransport，密钥在握手时校验 scope 与组织。

### 4.6 密钥管理 UI（设计见 §6.6）

密钥页三件套：**密钥列表**（状态/范围/配额用量条）、**创建向导**（名称→范围→绑定项目→过期→一次性展示）、**使用分析**（按日调用量、按工具分布、最近 20 条调用审计）。

## 5. 面向商业化的数据模型演进

在现有 5 表基础上新增（阶段二迁移，向后兼容）：

```sql
-- 账户与租户
CREATE TABLE users (
    id VARCHAR(64) PRIMARY KEY,
    email VARCHAR(255) UNIQUE NOT NULL,
    password_hash TEXT,                       -- 魔法链接/OAuth 用户为 NULL
    name VARCHAR(128),
    avatar_url TEXT,
    email_verified BOOLEAN DEFAULT FALSE,
    created_at TIMESTAMPTZ DEFAULT now()
);
CREATE TABLE organizations (
    id VARCHAR(64) PRIMARY KEY,
    name VARCHAR(255) NOT NULL,
    slug VARCHAR(64) UNIQUE NOT NULL,
    created_at TIMESTAMPTZ DEFAULT now()
);
CREATE TABLE memberships (
    user_id VARCHAR(64) REFERENCES users(id) ON DELETE CASCADE,
    org_id VARCHAR(64) REFERENCES organizations(id) ON DELETE CASCADE,
    role VARCHAR(32) DEFAULT 'member',        -- owner | admin | member | viewer
    PRIMARY KEY (user_id, org_id)
);

-- MCP 密钥
CREATE TABLE api_keys (
    id VARCHAR(64) PRIMARY KEY,
    org_id VARCHAR(64) REFERENCES organizations(id) ON DELETE CASCADE,
    created_by VARCHAR(64) REFERENCES users(id),
    name VARCHAR(128) NOT NULL,
    key_prefix VARCHAR(16) NOT NULL,          -- vhk_live_7Kd9（展示用）
    key_hash TEXT NOT NULL,                   -- SHA-256(salt + key)
    salt VARCHAR(64) NOT NULL,
    scopes VARCHAR(255)[] NOT NULL DEFAULT '{context:read}',
    project_ids VARCHAR(64)[],                -- 绑定的项目；空 = 组织内全部
    rate_limit INT DEFAULT 300,               -- 每分钟调用上限（管理员可调）
    last_used_at TIMESTAMPTZ,
    expires_at TIMESTAMPTZ,
    revoked_at TIMESTAMPTZ,
    created_at TIMESTAMPTZ DEFAULT now()
);
CREATE INDEX idx_api_keys_org ON api_keys(org_id, revoked_at);

-- 计量与审计
CREATE TABLE usage_events (
    id BIGSERIAL PRIMARY KEY,
    org_id VARCHAR(64) NOT NULL,
    api_key_id VARCHAR(64),
    event_type VARCHAR(64) NOT NULL,          -- mcp.tool_call / attachment.storage_gb_day ...
    metadata JSONB,
    created_at TIMESTAMPTZ DEFAULT now()
);
CREATE INDEX idx_usage_org_time ON usage_events(org_id, created_at);
CREATE TABLE audit_logs (
    id BIGSERIAL PRIMARY KEY,
    org_id VARCHAR(64) NOT NULL,
    actor_type VARCHAR(16) NOT NULL,          -- user | api_key
    actor_id VARCHAR(64) NOT NULL,
    action VARCHAR(128) NOT NULL,
    target VARCHAR(255),
    ip INET,
    created_at TIMESTAMPTZ DEFAULT now()
);
```

**迁移策略**：SQLite 阶段用 Prisma 迁移平滑加表；`projects` 增加 `org_id` 并回填「个人组织」（每个注册用户自动获得一个 Personal Org，历史数据零感迁移）。

### 5.1 新 API 面（商业化的门面）

```
POST   /api/auth/register | /login | /logout | /refresh
GET    /api/auth/oauth/:provider/callback
POST   /api/orgs                       创建组织
POST   /api/orgs/:id/members           邀请成员（发邮件）
GET    /api/orgs/:id/members | DELETE /api/orgs/:id/members/:uid
POST   /api/orgs/:id/api-keys          创建密钥（返回一次性明文）
GET    /api/orgs/:id/api-keys          列表（掩码）
POST   /api/orgs/:id/api-keys/:kid/rotate   轮换
DELETE /api/orgs/:id/api-keys/:kid          撤销
GET    /api/orgs/:id/api-keys/:kid/usage    用量分析
GET    /api/orgs/:id/audit-logs
GET    /api/orgs/:id/usage              计量查询（出账依据）
```

## 6. 2026 主题 UI 设计规范

### 6.0 设计基底：白泽观智设计语言

VibeHub 2026 主题以 **baize-guanzhi（白泽观智）** 的设计语言为基底并面向「双端工作台」场景演化：

| 基因 | 取值 | 演化方向 |
| --- | --- | --- |
| 暖纸底色 | `#F7F3EC` / `#F6F3EB` | 保留为「Daylight 纸白」主题；看板列改用同族暖灰区分层级 |
| 香槟金 | `#B8924E` / `#E8C871` | 升级为**品牌金**，专用于 AI 生成内容标识与高级权益，避免滥用 |
| 深藏青 | `#1F355A` | 升级为主操作色（替代通用蓝紫），传递专业与信任 |
| 玻璃拟态 | `rgba(255,255,255,0.80)` + blur | 保留为 2.0 版：更轻的透明度 + 1px 高光边 |
| 网格背景 | 40px 淡网格 | 保留于登录/营销页；工作台内仅在空状态使用 |
| 光标聚光/萤火虫 | 金色径向光晕 | 收敛为克制版本：仅登录页与命令面板 |
| 线性图标 | stroke-width 1.8 | 保留（Lucide 原生即此规范） |
| 圆角 | 按钮 6-8px、卡片 10-12px | 提升一档：按钮 10px、卡片 14px、面板 20px（2026 更柔） |
| 字体 | Noto Sans SC / PingFang SC | 增加可变字体与衬线品牌字（Noto Serif SC）用于 Logo 与大标题 |

### 6.1 2026 设计原则

1. **暗色优先，双主题平行**：工作台默认 Midnight（深蓝黑），营销与文档站默认 Daylight（纸白）；两套都达到 WCAG AA。
2. **空间层叠（Spatial Layering）**：界面按 Z 轴分层——背景（纸）/ 面板（玻璃）/ 浮层（实底 + 投影）/ 模态（遮罩 + 景深模糊），用阴影与模糊表达层级，而非粗边框。
3. **Bento 网格**：仪表盘、用量分析、模板市场统一采用便当格布局，单元格圆角 20px、间距 16px。
4. **有目的的动效**：所有动画必须承担反馈职责（状态确认、空间关系、注意力引导）；时长 ≤ 300ms；全局尊重 `prefers-reduced-motion`。
5. **AI 与人类创作者的可视区分**：AI 写入的内容（MCP 回填的状态、AI 便签）统一带香槟金微标与星尘底纹，人类内容为中性色——这是产品核心叙事的视觉化。
6. **信息密度可调**：紧凑/舒适双档（设置项），开发者默认紧凑（一屏看更多卡片）。

### 6.3 字体排印


**动效规范**：
- 悬停反馈：背景 8% 白色叠加，`--dur-fast`
- 卡片拖拽：跟手缩放 1.02 + `--shadow-2`，落位时目标列 120ms 高亮脉动一次
- 弹层进入：`scale(0.96) + opacity`，`--ease`，`--dur-base`；退出一律更快（140ms）
- SSE 到达的卡片更新：卡片顶部 1px 金色流光扫过（400ms），告知「这是 AI 刚改的」
- `prefers-reduced-motion: reduce` 时全部动效降级为 120ms 交叉淡入

### 7.3 Open-Core 边界

**开源（Apache-2.0）**：核心引擎、MCP Server、本地存储、看板前端、CLI。
**云版专有**：账户与组织、密钥计量、团队 SSE 节点、SSO、审计、托管存储。
原则：自托管用户永远可以「一个人完整使用」；云版卖便利（免运维）、协作与治理，绝不裁剪核心能力逼升级。

## 11. 合规与隐私

- **个保法 / GDPR**：最小化收集（邮箱、昵称、头像）；提供数据导出与账号注销（30 天软删 + 级联清除附件物理文件）。
- **数据驻留**：Enterprise 支持区域选择（国内版 / 国际版分集群）。
- **审计**：所有认证、密钥操作、成员变更、状态回填（AI 写入）留痕，Enterprise 可导出 CSV。
- **SLA**：Enterprise 承诺 99.9% 可用性，故障 30 分钟内响应。
- **漏洞披露**：security@ 邮箱 + 90 天披露窗口，Hall of Thanks。
