## 8.2 端到端验收脚本（浏览器 + CLI 混合）

### 场景 A：空系统冷启动（5 分钟可用）

1. `docker compose up -d` 起全新容器（库与附件均为空卷）。
2. 打开 Web → 自动落在登录页（纸白 + 网格 + 金色聚光渲染正确）。
3. 注册第一个账号 `owner@team.com` → 直接进入看板 → 空态显示「还没有缺陷，按 C 或粘贴截图开始」。
4. 成员页显示 1 人角色 Owner。
5. 第二个浏览器（隐身窗）注册 `dev@team.com` → 角色 Member，成员页出现 2 人。
6. 关闭注册开关（Owner 在设置页）→ 隐身窗登录页无注册 Tab，提示联系管理员。
7. Owner 在成员页把 dev 提为 Admin → dev 刷新后看到「成员」「密钥」导航。

### 场景 B：人的闭环（录入→指派→修复→验证）

1. Member 按 `C` → 粘贴一张截图 → 选模板「缺陷报告」→ 写标题 → ⌘↵。
2. 看板 Open 列出现卡片，含缩略图；Owner 端（另一浏览器）**不刷新**看到卡片滑入（SSE）。
3. Owner 拖卡片到 In Progress → 活动流出现一条 `user: open → in_progress`。
4. Owner 指派给 dev → 卡片显示 dev 头像。
5. Member 打开详情 → 复现步骤/期望/实际齐全 → 追加评论「疑似 NPE」。
6. Owner 拖到 Resolved 并填修复说明 + commit hash（详情页内联）。
7. dev 拖到 Verified → Closed；活动流六条记录按时间线渲染。
8. 从 Closed 拖回 In Progress 被拒 → 点「重开」填原因 → reopenedCount=1，卡片显示 ↻1。

### 场景 C：AI 的闭环（MCP 全链路）

1. Admin 在密钥页创建密钥（scope 全开）→ 复制 MCP 配置 JSON。
2. 配置到 IDE（或直接 stdio 测试脚本）→ `get_project_context` 返回 Open 缺陷简报。
3. `read_attachment_text` 分片读一个大日志；`inspect_image_asset` 拿 base64 截图。
4. `add_bug_comment`：「已定位 LoginController:88」→ Web 端活动流即时出现金色 AI 记录。
5. `update_bug_status` → resolved + commit → 看板卡片**不刷新**移入 Resolved（5s 轮询兜底验证）。
6. `upload_attachment` 把一段堆栈日志贴回该缺陷 → 文件页出现金色 AI 徽章文件。
7. 撤销该密钥 → 再用它调工具 → MCP 启动失败，stderr 人话错误。

### 场景 D：治理

1. Member 上传 3 个文件 → 「我的」视角只见自己的；Admin「全部」可见。
2. Member 删自己文件 → Toast 撤销恢复成功；再删 → 回收站出现 → 30 天倒计时。
3. Admin 移除 dev → dev 登录被拒（账号已禁用）；其历史缺陷/文件仍在，作者显示快照名。
4. Owner 转让 Owner 给 dev → 角色互换 → owner 降级后看不到成员页。
5. 用量页/密钥页数字与审计表行数与实际操作次数一致（抽查三个数）。

## 8.4 Docker 复核清单（按《容器化部署规范》§9 执行）

- [ ] `docker compose up -d`：缺 `.env` 项即启动失败并提示生成命令；补齐后一键起容器
- [ ] 容器内 `psql -c '\dx'` 可见 **vector** 扩展（pgvector 预置生效）
- [ ] 首次启动自动 `migrate deploy`，空系统；`/api/health` 200，:3210 是登录页
- [ ] `docker compose restart` 数据不丢（pg 数据卷 + /data 附件卷分离）
- [ ] `docker exec vibehub pg_dump -U vibehub vibehub` 有输出（备份通道）
- [ ] SSE MCP：`curl -N localhost:3210/mcp/sse` 无密钥被拒；带密钥 initialize 成功
- [ ] 5432 未映射到宿主机（compose ports 只有 3210）
- [ ] 构建体积 ≤ 1.2GB；镜像标签 `vibehub:latest`
- [ ] `docker exec vibehub du -sh /data` 与宿主机卷大小一致（附件写卷成功）
