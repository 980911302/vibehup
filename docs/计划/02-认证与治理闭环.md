# 步骤 02 · 认证与治理闭环

> 目标：闭合「身份闭环」——注册/登录/刷新/登出全链路 + 成员管理（改角色/禁用/移除/建号）+ 操作审计 + 注册开关。首位注册用户自动成为 Owner。所有既有 API 加上登录守卫。

## 2.2 认证服务契约

```ts
// services/auth.ts
export async function register(input: { email: string; password: string; name: string }): Promise<{
  user: PublicUser; accessToken: string; refreshToken: string;
}>
// 规则：
// - email 规范化（trim+lowercase），格式校验；已存在 → 409
// - validatePasswordStrength 校验（≥8 位且含字母数字）
// - users 表为空 → role=owner，否则 role=member
// - 写 UsageEvent(eventType='auth.register')

export async function login(input: { email: string; password: string }): Promise<{
  user: PublicUser; accessToken: string; refreshToken: string;
}>
// 规则：
// - 用户不存在或密码错 → 统一 401「邮箱或密码错误」（防枚举）
// - status=disabled → 403「账号已被禁用，请联系管理员」
// - 成功 → 发令牌族（familyId 同族），更新 lastLoginAt
// - 写 UsageEvent('auth.login', metadata: { ip, ua })

export async function refresh(refreshToken: string): Promise<{ accessToken: string; refreshToken: string }>
// 规则：
// - 哈希查库；不存在/已撤销/过期 → 401
// - **重放检测**：若用于刷新的令牌此前已被消费过（同 family 出现已撤销记录）→ 吊销整个 family 并 401「登录态异常，请重新登录」
// - 轮换：旧令牌 revokedAt=now，同 family 发新令牌

export async function logout(refreshToken: string): Promise<void>   // 撤销该令牌
export async function me(userId: string): Promise<PublicUser & { stats: {...} }>
export async function changePassword(userId: string, oldPwd: string, newPwd: string): Promise<void>
// 规则：改密后吊销该用户全部 refresh 令牌（强制重新登录）
```

`PublicUser` 序列化（**绝不含 passwordHash**）：

```json
{ "id": "usr_...", "email": "...", "name": "...", "role": "owner",
  "status": "active", "last_login_at": "...", "created_at": "..." }
```

## 2.3 路由契约

```
POST /api/auth/register    { email, password, name }
     → 201 { user, access_token, refresh_token, expires_in: 900 }
     → 409 { error: { code: 'EMAIL_TAKEN' } }
     → 400 密码强度不足（message 为人话，如「密码需同时包含字母和数字」）

POST /api/auth/login       { email, password }
     → 200 { user, access_token, refresh_token, expires_in: 900 }
     → 401 { code: 'INVALID_CREDENTIALS', message: '邮箱或密码错误' }
     → 403 { code: 'ACCOUNT_DISABLED' }

POST /api/auth/refresh     { refresh_token }
     → 200 { access_token, refresh_token, expires_in }
     → 401 { code: 'TOKEN_REUSED' }（重放，已吊销全族）

POST /api/auth/logout      { refresh_token }  → 204
GET  /api/auth/me          （Bearer）→ { user, stats: { bugs_created, files_uploaded, mcp_calls_30d } }
PATCH /api/auth/me         { name? } → { user }
POST /api/auth/me/password { old_password, new_password } → 204（吊销全部会话）

GET  /api/users            （Admin+）→ [ { ...publicUser, stats } ]  支持 ?status=&role=&q=（拼音/邮箱/姓名检索）
POST /api/users            （Admin+）{ email, name, password?, role? } → 201（REGISTRATION_OPEN=false 时管理员建号；密码缺省随机生成并返回一次性明文）
PATCH /api/users/:id       （Admin+）{ role? | status? } → { user }
     → 规则：不能禁用/降级最后一个 Owner；不能改自己角色（防误锁）
DELETE /api/users/:id      （Admin+）→ 204；规则同上 + 其创建的文件/缺陷保留（created_by 保留快照名），不级联删除业务数据
POST /api/users/transfer-ownership  （Owner）{ target_user_id } → 204（Owner 转让：双方角色互换）
```

## 2.4 鉴权中间件契约

```ts
// plugins/authenticate.ts
declare module 'fastify' {
  interface FastifyRequest { user?: { id: string; role: string; email: string } }
  interface FastifyInstance {
    authenticate: (req, reply) => Promise<void>;      // 校验 Authorization: Bearer <jwt>，失败 401 { code:'UNAUTHORIZED' }
    requireRole: (...roles: Role[]) => (req, reply) => Promise<void>;  // 403 { code:'FORBIDDEN', message:'需要管理员权限' }
  }
}
```

接线方式：`index.ts` 中每个业务路由 `addHook('onRequest', app.authenticate)`；管理类路由再叠加 `app.requireRole('owner','admin')`。**MCP 路由不经 HTTP，不受影响。**

## 2.5 人性化细节

- 登录失败信息统一「邮箱或密码错误」，不提示「用户不存在」（防枚举）。
- 注册成功即登录（直接发令牌），不逼用户二次登录。
- 禁用账号的用户正在使用的 access token 在 15 分钟内自然过期；管理员可位的「移除」不级联删数据，只摘身份——业务数据保留并显示原作者名快照。
- 「成员」页每行操作前若有风险（禁用 Owner、改自己角色），按钮置灰 + tooltip 说明原因。
- 审计页（步骤 07）按人/动作/时间三维筛选，支持导出 CSV。

## 2.6 验收标准

- [ ] 空库启动 → 注册第一个用户 → `role=owner`；第二个注册 → `member`
- [ ] 登录拿令牌 → 带令牌访问 `/api/projects` 200；不带 → 401 `UNAUTHORIZED`
- [ ] refresh 正常轮换；**同一 refresh 令牌二次使用 → 401 TOKEN_REUSED 且同族全部失效**
- [ ] 改密后旧 refresh 全部 401
- [ ] member 调 `PATCH /api/users/:id` → 403 FORBIDDEN；admin 可
- [ ] 禁用最后一个 owner 被拒绝（业务错误码 `LAST_OWNER`）
- [ ] 任何接口响应中无 `password_hash` 字段（grep 测试断言）
- [ ] UsageEvent 有 register/login 记录；`GET /api/auth/me` 返回 stats
- [ ] 上传接口产出的 attachment 带 `uploaded_by`；`GET /api/attachments?mine=true` 只回自己的
