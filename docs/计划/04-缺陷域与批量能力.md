## 4.2 状态机契约（唯一真理源）

R83 起（用户决定）：

```
open ──► in_progress ──► resolved ──► verifying ──► verified（修复完成的终点）
  │            │              │  ◄─────────┘ 放回待验证（不需原因）
  └──► closed ◄┴──────────────┘      closed 只用于重复 / 不修 / 无法复现，必须写 resolution_notes
回流到 open/in_progress（从 resolved / verifying / verified / closed）= 重开，必须带 reopen_reason；
从 verifying 打回在评论流记为「验证不通过」。每次流转记录 status_changed_at + 操作人（用户名 / 密钥名）。
```

- 合法迁移表在 `services/bug-flow.ts`（`bugs.ts` 重导出）的 `BUG_TRANSITIONS`，非法迁移 400 `INVALID_TRANSITION`，message 为人话（中文状态名）：「不能从「已解决」直接改为「已验证」，可以改为：验证中 / 进行中 / 待处理 / 已关闭」。
- **任何状态变化自动写 BugComment**（authorType=user|ai），形成活动流，前端详情页直接渲染。
- `reopenedCount` 只增不减，看板卡片显示「↻ 2」角标（被反复打回的缺陷一眼可见）。

## 4.3 API 契约

```
# 缺陷扩展字段
POST   /api/bugs                { ..., assignee_id?, priority?, due_date?, labels?, template_id? }
PATCH  /api/bugs/:id            同上；status 变化走状态机校验

# 批量（Excel 式）
POST   /api/bugs/batch          { ids: string[], action: 'status'|'assign'|'label'|'priority'|'move_project'|'delete',
                                  payload: { status?, assignee_id?, labels?, priority?, project_id? } }
                                → { updated: n, skipped: [{id, reason}] }  部分失败不中断，逐条报原因

# 评论 / 活动流
GET    /api/bugs/:id/comments   → [{ id, author_type, author:{name}|null, content, created_at }]（倒序）
POST   /api/bugs/:id/comments   { content } → 201

# 模板
GET    /api/bug-templates       → 首次调用惰性创建三个默认：
        「缺陷报告」(severity 默认 normal)、「线上事故」(critical + 时间线骨架)、「需求跟进」(low)
POST   /api/bug-templates / PATCH / DELETE   （Admin+ 可管理；Member 可用不可改）

# 保存视图（看板页的「我的筛选」）
GET    /api/saved-views?entity=bug
POST   /api/saved-views         { entity, name, filters, sort, columns, is_default? }
PATCH  /api/saved-views/:id     DELETE /api/saved-views/:id

# 导入导出
GET    /api/bugs/export?project_id=&format=csv   → text/csv（BOM 头，Excel 直接打开中文不乱码）
POST   /api/bugs/import         multipart CSV    → { imported: n, failed: [{row, reason}] }
```

## 4.4 CSV 契约（导入导出共用一种格式）

```csv
标题,严重度,状态,指派邮箱,标签,优先级,截止日,复现步骤
"按钮点击无响应",high,open,dev@team.com,"ui,p0",high,2026-10-01,"1. 进入设置页 2. 点击保存"
```

- 导入按行校验：标题必填；severity/status/priority 枚举校验；指派邮箱匹配不到用户 → 该行失败并说明（不静默丢）；标签 `,` 分隔。
- 失败行返回行号+原因，全部成功才提示绿，部分成功提示黄「已导入 N 条，M 行失败，点击查看原因」。

## 4.5 批量操作产品规则（人性化）

- 批量改状态：同状态目标合并为一次操作；跨项目移动需二次确认（唯一例外）。
- 批量删除走 5 秒撤销 Toast（删缺陷 + 其附件进回收区，撤销时从 trash 恢复）。
- 批量面板常驻底部：显示「已选 N 项」+ 操作按钮组 + 清除选择；⌘A 全选当前筛选结果，Esc 清除。
- 视图保存的 `columns` 控制卡片/列表列的显隐与顺序（Excel 式列管理）。

## 4.6 验收标准

- [ ] 非法状态迁移返回 400，message 含「只能」的人话提示
- [ ] resolved → open 直接迁移被拒绝，需 reason；带 reason 后 reopenedCount+1 且评论流有记录
- [ ] 每次 PATCH 改状态后 `GET /comments` 多一条 author_type=user 的记录
- [ ] `POST /api/bugs/batch` 混合合法/非法 id → 部分成功，返回 skipped 及原因
- [ ] CSV 导出 UTF-8 BOM，Excel 打开中文正常；导出再导入 round-trip 字段一致
- [ ] 模板接口首次调用自动创建 3 个默认模板；Member 删模板 403
- [ ] 视图保存后 `GET /api/saved-views?entity=bug&is_default=true` 可设为默认
- [ ] assignee 序列化输出 `{ id, name }` 而非裸 id
