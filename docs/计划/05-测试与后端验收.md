## 5.2 测试基建契约

**数据库：测试一律跑真正的 PostgreSQL + pgvector**（与生产同引擎，杜绝 sqlite/postgres 行为分裂）。用一次性容器提供，不依赖本机安装：

```bash
# scripts/test-db.sh：起一次性 pg 容器（若已在运行则复用），输出连接串
docker run -d --name vibehub-test-db -e POSTGRES_PASSWORD=test \
  -p 55432:5432 pgvector/pgvector:pg17
# TEST_DATABASE_URL=postgresql://postgres:test@127.0.0.1:55432/postgres
```

`src/test-setup.ts` 改为：读 `TEST_DATABASE_URL`（缺省指向上面容器）→ `CREATE EXTENSION IF NOT EXISTS vector` → `prisma migrate deploy` → 每用例前 `resetDb()`。

```ts
// test-helpers.ts
export async function resetDb(): Promise<void>   // 按外键逆序 TRUNCATE 全部表（postgres 语义）
export async function createUser(overrides?: Partial<{ email: string; password: string; name: string; role: Role; status: string }>)
export async function authHeaders(app: FastifyInstance, email = 'owner@t.com', password = 'abcd1234'): Promise<Record<string, string>>
export async function createApiKey(overrides?: { scopes?: string[]; rateLimit?: number }): Promise<{ key: string; id: string }>
```

CI/无 docker 机器的降级路径：允许 `TEST_DATABASE_URL` 指向任何可达 postgres（含托管库），测试代码不感知来源。

## 5.4 验收脚本 `scripts/acceptance.sh` 行为

1. 重建测试库并 `prisma migrate deploy`
2. `vitest run`（全量）
3. 启动服务（随机端口）→ curl 冒烟：health、注册、登录、带/不带令牌访问、上传、建缺陷、密钥创建
4. 输出 `PASS/FAIL` 汇总，失败即非零退出

## 5.5 验收标准

- [ ] `npx vitest run` 全绿，用例数 ≥ 100
- [ ] 覆盖率（`--coverage`）核心 services 行覆盖 ≥ 80%
- [ ] `bash scripts/acceptance.sh` 退出码 0（内部先 `scripts/test-db.sh` 起库）
- [ ] 测试库与生产同引擎（postgresql+vector），无 sqlite 分支代码
- [ ] CI 可复现：同一提交两次运行结果一致（无随机依赖，除 ID 后缀外）

## 5.6 验证命令

```bash
# 一次性起测试库（之后测试/验收都连它）
bash scripts/test-db.sh
cd vibehub/server
export TEST_DATABASE_URL=postgresql://postgres:test@127.0.0.1:55432/postgres
npx vitest run --coverage
bash scripts/acceptance.sh
```
