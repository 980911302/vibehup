# VibeHub 团队单机版 · 产品设计与实施总纲

> 产品观：**像 Excel 一样**——打开就会用（一张表、一个粘贴框），但每个单元格背后都有完整能力。
> MCP 不是附属功能，而是产品的**另一半身体**：人在这边录入，AI 在那边消费与回填，两边毫秒级双向同步。
> 本套文档的每个步骤都可独立执行、可验收，且共同构成一个**逻辑闭环**的产品，而不是功能堆叠。

---

## 0. 产品哲学（设计师三原则）

1. **表面极简**：默认流程只有两步——「粘贴截图、写一句话、⌘+Enter」。高级能力（指派、标签、模板、批量、导入导出）全部藏在三层层级之下：快捷键、右键菜单、设置页。
2. **内里极深**：每个实体都有完整状态机、完整字段、完整历史、完整审计。用户可以在第一周只用 10% 的功能，第三个月发现还有 90% 可挖——但没有任何一天会觉得「缺东西」。
3. **闭环高于功能**：任何单向能力都不许上线。「录入」必须连得到「消费」，「修复」必须回得到「验证」，「禁用」必须连得到「数据移交」。下文 §2 定义五大闭环，所有步骤文档都服务于闭环闭合。

## 1. 产品能力全景（Capability Map）

### 1.1 人的世界（Web 端）

| 域 | 基础能力（默认路径） | 深度能力（进阶路径） |
| --- | --- | --- |
| 缺陷 | 粘贴建单、拖拽改状态、卡片看板 | 指派成员、标签、优先级、截止日、复制单、模板、批量编辑、内联改标题、视图保存（筛选+排序+列显隐）、CSV 导入导出、活动流、评论 @人 |
| 文件 | 粘贴上传、缩略图网格、点开大图 | 我的/全部视角、归属转移、批量删除、空间用量、类型筛选、搜索、文本在线高亮查看（分片+grep）、直链分享、保留期治理 |
| 随手记 | 记一笔、Markdown、标签过滤 | 置顶、归档、转缺陷（一键把便签升级为缺陷）、拖拽排序 |
| 任务 | 列表、三态 | 关联缺陷、优先级、指派、批量 |
| 项目 | 切换、创建 |  Slug 编辑（AI 匹配用）、归档、统计、删除（二次确认+数据说明） |
| MCP 密钥 | 创建、复制 | Scope 最小权限、绑定项目、速率限制、轮换（重叠期）、撤销、用量图表、调用审计、到期提醒 |
| 成员 | 管理员可见成员列表 | 改角色、禁用/启用、移除、数据移交归属、注册开关 |
| 全局 | ⌘K 搜索、最近访问 | 命令面板导航（G+B/G+F/G+P/G+K/G+M）、快捷键帮助（?）、撤销 Toast、主题切换 |

### 1.2 AI 的世界（MCP 端）

原则：**AI 是超级用户，不是特权用户**。AI 能做人都能做的全部事，且每一次写入都可审计、可回滚、可追溯。

| 类别 | 工具（规划 14 个，见步骤 03） |
| --- | --- |
| 上下文读取 | get_project_context、list_bugs、get_bug_detail、list_notes、search |
| 资产消费 | read_attachment_text（分片+grep）、inspect_image_asset（降采样+base64） |
| 写入回填 | update_bug_status、add_bug_comment、append_scratchpad、create_bug |
| 资产生产 | upload_attachment（AI 把自己抓到的日志/截图贴回工单） |
| 任务协同 | list_tasks、update_task |

**Token 经济学**（防止撑爆上下文，全工具统一）：
- 列表类工具默认最多 20 条 + `has_more`；detail 类只返回必要字段，长文本默认截断到 500 字符并给出 `read_attachment_text` 提示；
- 图片一律先降采样到最长边 1080px，`return_mode` 默认 path（本地路径免费），base64 需显式声明且有 4MB 上限；
- 所有输出 snake_case 扁平结构，无嵌套超过两层。

## 2. 五大闭环（产品骨架）

```
闭环① 缺陷生命周期
  录入(人粘贴 / AI 创建) → 指派(人或AI) → in_progress(AI 消费上下文+修复)
  → resolved(AI 回填 notes+commit) → verified(人验收) → closed
  ↘ 验证不通过 reopened → 回到 in_progress（活动流全程留痕）

闭环② 人机同步
  Web 任何写入 → SSE 即时推送同团队所有端
  MCP/AI 任何写入 → 用量打点 + 看板 5s 内轮询兜底 + 金色流光提示「这是 AI 刚改的」
  （单机单进程内 SSE 直通；MCP stdio 跨进程由轮询兜底——边界已在商业计划书说明）

闭环③ 资产生命周期
  上传(人粘贴/AI upload_attachment) → 归属(用户+项目+实体) → 消费(直链/分片/base64)
  → 治理(配额、保留期、孤儿清理：实体删除后文件移入回收区保留 N 天)

闭环④ 身份与治理
  注册 → 首位用户=Owner → 成员加入(自助/关闭注册后由管理员建号)
  → 角色(owner/admin/member/viewer) → 操作审计 → 禁用/移除(数据归属移交)
  → Owner 可转让

闭环⑤ 计量
  每次 MCP 调用/上传/登录 → usage_events → 用量看板(组织/密钥/人三个维度)
  → 配额阈值告警 → 管理员调配额
```

## 4. 数据模型（终态，当前已完成基础四表）

```prisma
User           id, email, passwordHash, name, role, status, lastLoginAt
RefreshToken   id, userId, tokenHash, familyId, expiresAt, revokedAt
ApiKey         id, name, keyPrefix, keyHash, salt, scopes, rateLimit,
               lastUsedAt, expiresAt, revokedAt, createdBy
UsageEvent     id, apiKeyId?, userId?, eventType, metadata, createdAt

Project        （既有） + archivedAt?  + createdBy?
Bug            （既有） + assigneeId? + priority? + dueDate? + labels(JSON)
               + reopenedCount?    —— 指派人、优先级、截止日、标签数组
BugComment     id, bugId, authorType(user|ai), authorId?, content, createdAt —— 评论/活动流
Task           （既有） + assigneeId?
Note           （既有） + pinnedAt? + createdBy?
Attachment     （既有） + uploadedBy?
BugTemplate    id, name, titleTemplate, fields(JSON：默认严重度/标签/复现步骤骨架), createdBy
SavedView      id, userId, entity, name, filters(JSON), sort(JSON), columns(JSON)
```

> 原则：单机单团队，不建 organizations 表；所有表不带 org_id（商业计划书的多租户是云版范畴，刻意不做）。

## 6. 人性化细节总则（所有步骤共同遵守）

1. **快捷键无处不在**：全局（C/⌘K/?/Esc/G+字母）、列表（J/K 上下移动、Enter 打开、X 多选、⌘A 全选）、表单（⌘Enter 提交、Tab 跳域）。
2. **粘贴优先**：任何页面 Ctrl+V 到图片 → 浮出「归属到哪个项目/缺陷」轻菜单，而不是只能去上传页。
3. **可撤销**：所有删除/批量操作走「5 秒撤销 Toast」，不弹确认框打断；只有「删项目」这类不可逆操作才二次确认。
4. **内联编辑**：标题、标签、指派、优先级全部点击即改，Enter 保存、Esc 取消——不开表单页。
5. **会教人的空状态**：每个空状态 = 一句人话 + 一个主操作按钮 +（可选）一行快捷键提示。
6. **错误信息带出路**：任何错误提示都要告诉用户「下一步做什么」，禁止裸错误码。
7. **AI 痕迹可见**：AI 写入的内容带金色星尘徽章 + 卡片顶部流光，让人随时知道「这是 AI 动的」。
8. **默认值即最佳实践**：新建缺陷默认当前项目 + 普通严重度 + 我未指派；新建密钥默认最小 scope + 90 天过期——安全与便利的默认都帮用户选好。
