# R90 下一轮设计：验收、交接与项目记忆

> 目标：把「AI 能干」变成「AI 干得可信、交得出去、团队记得住」。
> 约束：不新增一级入口，不再加一套大表单；四区仍是 今日 / 工作 / 上下文 / 设置。
> 状态：证据包 + 今日验收门 + MCP 身份/交接 + 站内通知 + 项目记忆 + 队列优先已实现；每日摘要/飞书、Work Item 合并待后续。

---

## 0. 一句话

**AI 填，人不填；证据先于状态；交接有主；记忆是压缩，不是仓库。**

这一轮只解决四个缺点：

1. 验收缺证据，人不敢点「通过」
2. AI 和人都不知道怎么把活交出去
3. 完成/打回/转交没有通知，只能靠打开页面碰
4. 笔记/文件/技能散着，AI 每次都要重新读一遍

---

## 1. 设计原则

| 原则 | 具体做法 |
| --- | --- |
| AI 填，人不填 | 证据、变更文件、测试结果由 AI 通过 MCP 写；人只做判断和补充一句原因 |
| 证据先于状态 | 没有交付证据的「已解决 / 待验证」，在今日页明确标「缺证据」，不能直接验收 |
| 一次只做一件事 | 今日卡片只放当前一步：开始验证 / 通过 / 打回；不堆状态按钮 |
| 默认收拢，按需展开 | 已完成自动归档；证据默认摘要一行，点开才看全量 |
| 移动端是行动端 | 手机只做：看今日、录一笔、验收/打回；不要求在小屏拖看板 |
| 不为功能加页面 | 证据进详情/今日卡，交接进详情，通知进顶栏，记忆进上下文页顶部 |

---

## 2. 验收闭环（优先级最高）

### 2.1 交付证据包（Evidence）

缺陷和任务共用一个 `evidence` JSON 字段（PostgreSQL `jsonb`，可空）：

```json
{
  "commit": "9f2c1ab",
  "pr_url": "https://github.com/org/repo/pull/123",
  "tests": "vitest 348 passed; E2E 14 passed",
  "changed_files": ["web/src/...", "server/src/..."],
  "screenshots": ["att_xxx", "att_yyy"],
  "notes": "首页白屏已修，390px 下补充了回归",
  "no_code_reason": null
}
```

- **AI 写入**：`update_bug_status` / `update_task` 增加 `evidence` 参数；AI 标记 `resolved` / `review` 时一并写。
- **人补充**：详情页「交付证据」区块可改；截图直接复用附件上传。
- **非代码任务**：允许 `no_code_reason`（如「只改了线上配置」），但仍要一句话说明，不能空着。
- **展示**：今日待验收卡只显示一行摘要 + 证据完整度（有/缺）；详情页看全量。

### 2.2 状态门（不破坏现有状态机）

- `resolved` / `review` 仍由 AI/人正常流转，不新增状态。
- 今日页验收时：
  - 有证据：显示「证据 4 项」，可直接「验收通过」。
  - 无证据：显示「缺证据」黄色提示，主按钮变为「补证据」；补完才可验收。
  - 非代码：可点「无需代码证据」，必须填一句 `no_code_reason`，才能验收。
- 服务端不硬拦历史数据；只在验收接口/UI 上做提示，避免破坏旧数据流转。

### 2.3 今日卡片的最终形态

```
待验收  3 件
[已解决] 首页白屏         2h
  证据：commit · PR · 348 tests   [查看]
  [开始验证] 或 [验收通过] [打回]
[验证中] 导出乱码          1h
  证据：commit · 截图 2 张
  [验收通过] [打回]
```

- 打回原因继续复用现有 `reopen_reason`，不另立字段。
- 通过/打回后 Toast + 卡片即时移除；失败保留现场并说明原因。

## 3. 交接（AI 与人都需要）

### 3.1 MCP 三个工具

| 工具 | 作用 | scope |
| --- | --- | --- |
| `get_me` | 我是谁：人类、密钥名、角色、可用能力、当前项目 | `context:read` |
| `list_members` | 团队里有谁：id / 名字 / 角色 / 当前负载 | `context:read` |
| `handoff_work` | 把缺陷/任务转给某人：实体、assignee、一句原因 | `bug:write` + `task:write` 按实体 |

- `get_me` 让 AI 知道「我代表谁、能做什么」，不再靠猜。
- `list_members` 默认只返回 active 成员；不返回邮箱等敏感字段，除非 admin。
- `handoff_work` 写 assignee + reason，记一条活动/通知；不允许转给 viewer 做写操作。
- 不新增表：转交记录先写 `usage_events`（MCP 调用）+ 实体评论/活动流；通知进第 4 节。

### 3.2 人侧

- 详情页负责人旁边加「转交」：选成员 + 一句原因。
- 今日「待我处理」顶部加「转给我」筛选（已有指派给我，复用）。
- 转交后原负责人收到站内通知；AI 转交时通知新负责人。

---

## 4. 通知（先做站内，飞书/CI 不做）

### 4.1 事件

- 指派给我 / 转交给我
- 待我验收（AI 标记 resolved/review）
- 打回给我（reopen_reason）
- 卡住提醒（复用 stale 阈值：验证中 >2h、进行中 >24h）
- 每日摘要（今天完成、待验收、卡住）

### 4.2 形态

- 顶栏铃铛 + 未读数；点开是右侧抽屉，不是新页面。
- 每条通知：谁、做了什么、一句话、直达链接；已读/全部已读。
- 每日摘要默认 18:00 生成一条站内通知；不做邮件/飞书，避免打扰。
- 通知只存扁平字段，不存敏感正文；30 天清理。

### 4.3 数据

```sql
notifications(
  id, user_id, type, title, body,
  entity_type, entity_id, project_id,
  read_at, created_at
)
```

- 写通知与业务写在同一个 service 事务后；失败隔离，不阻断主流程。
- 不做实时推送新表，复用现有 SSE 事件；前端铃铛轮询/SSE 刷新。

## 5. 项目记忆（上下文页顶部，不加新 Tab）

### 5.1 记忆不是仓库

- 在「上下文」页顶部加一张「项目记忆」卡：
  - 项目一句话
  - 关键决策 3–5 条（来自置顶笔记）
  - 术语/约定
  - 常用文件/技能入口
- 只展示「被置顶/被标记为决策」的内容，不自动把所有笔记塞进去。
- 编辑权：owner/admin/member；viewer 只读。

### 5.2 给 AI 的压缩上下文

- `get_project_context` 增加 `memory` 字段：上述摘要 + 最近 5 条决策；保持小。
- 不做向量（当前 `EMBEDDING_PROVIDER=none`），先靠关键词 + 置顶；等记忆量真的上来再评估。
- 搜索仍走现有 `/api/search`，结果中标出「来自项目记忆」。

## 6. 旧页面与移动端（细节收尾）

- 工作看板在 `<768px` 改为「列表 + 状态筛选」，不再横向拖六列；桌面保留看板。
- 旧 `/board`、`/tasks` 仍可用，但主导航不再出现；只在归档/回滚入口出现。
- 统一空态/骨架/错误文案；所有列表空态给一个主按钮（录一笔 / 去验收）。
- 27 个 MCP 工具不在 UI 里全量罗列；密钥页只给「常用工作流」三条 + 完整清单折叠。
- 不做：向量开启、飞书/CI 录入、手动归档（已完成自动归档已满足）。

---

## 7. 实施顺序（每步可独立上线）

1. **证据 + 今日验收门**（最影响信任）
2. **`get_me` / `list_members` / `handoff_work` + 转交 UI**
3. **站内通知 + 每日摘要**
4. **项目记忆卡 + `get_project_context.memory`**
5. **移动端列表 + 旧页面/空态收尾**

---

## 8. 验收标准

- 今日待验收：有证据可通过；缺证据不能直接通过；非代码证据可写原因通过。
- 证据可由 AI 通过 MCP 写入，也可由人在详情补充；刷新/重启不丢。
- `get_me` 返回正确的人类/密钥/角色；`list_members` 不泄露不该看的字段；`handoff_work` 后 assignee 与通知正确。
- 通知：未读数、已读、直达链接、30 天清理；通知失败不影响主业务。
- 项目记忆：置顶内容出现在上下文页与 `get_project_context.memory`；不开启向量也能用。
- 移动端 390px：今日验收、录单、归档列表可完成，无横向溢出。
- 全量门禁：`acceptance.sh` PASS、双端 tsc 0、next build 通过。
