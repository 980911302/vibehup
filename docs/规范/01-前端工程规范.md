# VibeHub 前端工程规范

> 适用范围：`web/`（Next.js 15 App Router + React 19 + TypeScript strict + Tailwind v4）。
> 目标：新成员 30 分钟内能按同一写法提交代码；任何组件可被任何人安全修改。

---

## 1. 目录结构（固定，不随意新增顶层目录）

```
web/src/
├── app/                        # 路由（App Router）
│   ├── (auth)/                 # 登录注册（无壳布局）
│   ├── (app)/                  # 侧边栏壳内页面：board/files/tasks/projects/keys/members/settings
│   ├── layout.tsx              # Providers 挂载
│   ├── globals.css             # token + 关键帧 + 基础层（唯一样式源）
│   └── page.tsx                # 重定向 /board
├── components/
│   ├── ui/                     # 无业务语义的基础组件（button/card/dialog/toast…）
│   ├── layout/                 # 壳：Sidebar/AppTopBar/CommandPalette/ShortcutsHelp
│   ├── board/  files/  tasks/  projects/  keys/  members/  settings/   # 按页面域分目录
│   └── shared/                 # 跨域复用（AttachmentPreview/AssetPreview…）
├── hooks/                      # use-*.ts：use-vibehub.ts（数据中枢）/ use-hotkeys.ts / use-media-query.ts
├── lib/                        # api.ts / auth.tsx / theme.tsx / toast.tsx / types.ts / search.ts / utils.ts
│   └── (业务服务层只准调 api.ts，禁止组件内直拼 fetch)
└── styles/                     # 仅允许 .css 片段（不得与 globals.css 争奇技淫巧）
```

## 2. 命名与文件约定

| 对象 | 规则 | 示例 |
| --- | --- | --- |
| 组件文件 | PascalCase.tsx，默认导出 + 具名导出 Props 类型 | `BugCard.tsx` / `export interface BugCardProps` |
|  hooks | use-kebab.ts，返回稳定对象 | `use-vibehub.ts` |
| 工具/服务 | kebab.ts | `api.ts`、`token-budget.ts` |
| 常量 | SCREAMING_SNAKE，集中在文件顶部 | `BUG_STATUSES` |
| 事件/数据类型 | types.ts 单一定义处，snake_case（与 API 对齐） | `interface Bug { status: 'open'… }` |
| CSS 类 | Tailwind 优先；组件根类用 `data-slot` 标注 | `<div data-slot="bug-card">` |
| 测试 | `*.test.ts(x)` 与被测同目录 | `BugCard.test.tsx` |

## 3. 组件规范

1. **函数组件 + TypeScript 严格**：props 必须显式类型；禁止 `any`（`unknown` + 收窄）；禁止 `React.FC`。
2. **基础组件一律 forwardRef**（button/input/dialog 等），透传 `className` 与原生属性；变体用 `cva`，样式合并用 `cn()`。
3. **组合优于配置**：组件通过 children/slots 组合，props ≤ 7 个；超出拆子组件。
4. **服务端组件优先**：App Router 中页面默认 Server Component；交互岛标注 `'use client'` 且尽量下沉到叶子。
5. **禁止跨域 import**：`components/keys/` 不得 import `components/board/`；共享上移 `shared/`。
6. **副作用边界**：数据请求只准在 hooks 或 Server Component；组件内禁止 `useEffect` 里 fetch（命令面板等特例须注释原因）。
7. **状态分层**：URL 状态（筛选/选中）→ `useSearchParams`；跨页状态（当前项目/主题/用户）→ Provider；其余本地 `useState`。禁止引入 Redux 等重状态库。

## 4. 数据访问规范

- **唯一入口 `lib/api.ts`**：所有请求经 `request<T>()` 包装（自动带 `Authorization`、401→refresh→重放一次→失败登出、统一错误形态）。
- 类型即契约：api.ts 返回类型必须与 `lib/types.ts` 完全一致；后端改字段 = 同步改 types + 编译错误驱动修复。
- 列表页数据流：`use-vibehub.ts` 统一持有（projects/board/notes/attachments/users/keys），页面只消费；子树刷新用 `refreshXxx()`，禁止页面自fetch。
- 实时：SSE（同进程）+ 5s 轮询兜底（跨进程 MCP）已在 hook 内实现，页面不感知。
- 乐观更新规范：拖拽改状态立即本地生效，失败回滚 + Toast；禁止半成功态停留。

## 5. 样式规范

1. **Token 化**：颜色/圆角/阴影/时长/缓动一律 `var(--*)`（来源《UI主题风格规范》§1）；`globals.css` 外禁止新 token。
2. Tailwind v4 原子类优先；重复三次以上的类组合必须抽组件；禁止 `@apply` 新语法混乱（仅允许在 globals.css 基础层）。
3. 动效实现：CSS 类/关键帧优先（`globals.css` 关键帧库）；JS 动画仅用于 FLIP 类交互且必须注释。
4. 类名合并必须 `cn()`；禁止字符串拼接 class。
5. 深色/浅色：一律双主题验证；条件样式用 token 覆盖，禁止 `dark:` 前缀散落（统一 `data-theme`）。

## 6. TypeScript 与质量门禁

- `strict: true`，`noUncheckedIndexedAccess: true`（数组访问必须判空）。
- 提交前本地三连：`npx tsc --noEmit` → `npx next lint`（若配置）→ `npm run build`。
- ESLint 规则红线：`no-explicit-any`、`no-floating-promises`（`void` 显式忽略）、`react-hooks/exhaustive-deps` 不得整体 disable（局部豁免须注释理由）。
- 单文件 ≤ 300 行；单函数 ≤ 50 行；超过必须拆分（复杂度是 review 不通过的硬指标）。

## 7. 测试规范（前端）

- 框架：Vitest + Testing Library；组件测试与被测文件同目录。
- 必测：有分支逻辑的组件（权限矩阵、状态机展示）、hooks（use-vibehub 的 SSE/轮询）、纯函数（search/token-budget/formatTime）。
- 选择器优先级：`getByTestId`（已埋点）> `getByRole` > `getByText`；禁止依赖 class 结构。
- 快照测试仅用于稳定布局组件，且 ≤ 3 处。

## 8. 无障碍与性能（合入硬标准）

- 所有可交互元素键盘可达 + `:focus-visible` 样式（规范 §5）。
- 动效遵守 reduced-motion 降级（规范 §1.4 铁律）。
- 图片：`next/image` 或固定宽高比占位；懒加载；服务端降采样产物优先。
- 单路由 JS ≤ 200KB gzip 预算；超限须在 PR 说明。

## 9. Git 与 PR 规范

- 分支：`feat/xxx`、`fix/xxx`、`refactor/xxx`、`docs/xxx`；禁止直推 main。
- Commit（Conventional）：`feat(auth): add refresh token rotation` / `fix(board): drag stale closure`；body 写动机而非过程。
- PR 模板 checklist（必须全过）：
  ```
  - [ ] tsc / build 通过
  - [ ] 相关测试通过（新增用例覆盖分支）
  - [ ] 双主题截图（深/浅）附 PR
  - [ ] 动效符合《UI主题风格规范》（折叠/加载/关闭至少自查）
  - [ ] 无 console 错误/警告
  - [ ] API 变更同步 types.ts 与 README
  - [ ] 文件 ≤300 行 / 函数 ≤50 行
  ```

## 10. 目录即文档

每页目录顶部放一个 `README.md` 片段（≤20 行）：页面职责、数据来源（哪个 hook）、关键交互索引。新人改任何页面前先读它。
