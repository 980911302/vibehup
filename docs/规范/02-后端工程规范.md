# VibeHub 后端工程规范

> 适用范围：`server/`（Node 24 + TypeScript strict + Fastify 5 + Prisma 6 + **PostgreSQL 16/17 + pgvector**，单容器部署）。
> 目标：三层边界清晰、错误可预期、测试可信赖、安全默认开启。

---

## 1. 分层架构（严格单向依赖）

```
routes/        HTTP 边界：解析参数、调 service、序列化响应。禁止写业务逻辑。
  ↓ 只准向下
services/      领域逻辑：事务、状态机、校验、事件发布。禁止碰 Fastify 对象。
  ↓
core/          横切基础设施：prisma 单例、jwt、password、ids、events、errors、serialize、search。
mcp/           MCP 边界：调 services（与 routes 平级，共享 services），stdout 只走 JSON-RPC。
plugins/       Fastify 装饰器（authenticate/requireRole）。
config.ts      环境配置唯一出口。
```

规则：`routes → services → core`；`services` 之间可互相调用（bugs→attachments）；**禁止 routes 直连 prisma**（search 路由例外已逐步收敛到 service）。

## 2. 目录结构

```
server/src/
├── index.ts            # buildServer() + main()；测试用 buildServer 注入
├── mcp-entry.ts        # stdio 入口
├── config.ts           # env 唯一出口
├── plugins/            # authenticate.ts
├── core/               # prisma.ts errors.ts events.ts ids.ts jwt.ts password.ts
│                       # search.ts serialize.ts tokens.ts
├── services/           # 每实体一个文件 + *.test.ts
├── routes/             # 每实体一个文件 + api.test.ts
└── mcp/                # server.ts tools.ts context.ts scopes.ts usage.ts token-budget.ts
prisma/                 # schema.prisma + migrations/（禁手改 migration）
scripts/                # acceptance.sh
```

## 3. API 设计规范

1. **REST + snake_case JSON**；响应体字段与序列化函数一一对应（`core/serialize.ts`），禁止裸出 Prisma 模型（历史教训：register/search 路由曾因裸出模型导致前端崩溃）。
2. 统一错误体：
   ```json
   { "error": { "code": "VALIDATION_ERROR", "message": "人话，告诉用户下一步做什么" } }
   ```
   错误码枚举：`VALIDATION_ERROR / NOT_FOUND / UNAUTHORIZED / FORBIDDEN / EMAIL_TAKEN / INVALID_CREDENTIALS / ACCOUNT_DISABLED / TOKEN_REUSED / LAST_OWNER / INVALID_TRANSITION / PAYLOAD_TOO_LARGE / INTERNAL_ERROR`。
3. 状态码：200/201/204/400/401/403/404/409/413/429；业务失败一律 `AppError` 子类，route 不 try-catch。
4. 分页：`{ items, total, page, page_size }`；游标场景用 `has_more + next_cursor`（MCP）。
5. 写操作必须返回更新后实体（人话：让前端能直接刷新，不用再 GET）。
6. 所有列表接口必须可 `q` 检索（拼音）且默认上限 ≤500。

## 4. 鉴权与安全规范

- 密码：scrypt（N=16384,r=8,p=1,64B），格式 `scrypt$N$r$p$salt$hash`；强度校验函数统一出口。
- 令牌：access JWT HS256 15min；refresh 不透明随机 32B，DB 存 SHA-256，**一次性 + family 重放检测**；改密/禁用即吊销。
- 防枚举：登录失败统一「邮箱或密码错误」；注册成功不透露邮箱是否存在（409 除外，需产品评审）。
- 中间件链：`app.authenticate` → `app.requireRole(...)`；401/403 错误码固定。
- 上传：`@fastify/multipart` limits 全局收紧；MIME 白名单校验 + 扩展名二次校验；路径禁止用户可控（ID 生成，不信任文件名）。
- 速率限制：登录/注册/发信按 IP+账号双维；API Key 按 `rate_limit` 字段 QPM。
- 密钥：明文一次性返回；存储只留 prefix+hash+salt；scope 最小权限默认。
- 任何响应禁止出现 `password_hash`/`key_hash`/`salt`（测试断言守住）。

## 5. Prisma 与迁移规范

- Schema 是唯一真相；migration 只能 `prisma migrate dev/create` 生成，**禁手写 SQL 迁移**（除非 data migration 并注释）。
- 迁移必须可重复：`migrate deploy` 用于生产/测试/Docker。
- 查询规范：N+1 用 `include`/`Promise.all` 收敛；列表页 `take` 硬上限；写操作用 `$transaction` 包事务。
- 软删除/回收：附件删除 = 元数据删 + 文件移 `data/trash/`；禁物理直删。
- 字段演进只加不改语义；snake_case 由 `@map` 保证，查询代码用驼峰。

## 6. 事件与实时规范

- 业务写入成功后 `eventBus.publish(...)`，事件类型收窄在 `core/events.ts` 联合类型内，禁止散落字符串。
- SSE 端点：注释心跳 25s；客户端断开必须解绑（onRequest 无泄漏）。
- MCP 跨进程写入：打点 UsageEvent，Web 端 5s 轮询兜底（已知边界，README 注明）。
- 事件负载扁平：`{ type, projectId, entityId }`，不带全量数据。

## 7. MCP 专属规范

- **stdout 只有 JSON-RPC**：日志一律 `console.error`；测试断言 stdout 纯净（现有用例保持）。
- 工具实现放 `mcp/tools*.ts`，经 `guard(scope, fn)` 统一包装：scope 校验 → 执行 → `recordToolCall` 打点 → Token 经济学校形（`token-budget.ts`）。
- 工具 description 是给 AI 的 prompt：必须写清使用时机、分页行为、截断策略。
- 错误：领域错误返回 `{ content, isError: true }`，禁止 throw 穿协议层。
- 启动即失败：密钥无效/过期时进程退出并 stderr 人话说明，禁止静默降权。

## 8. 测试规范

- 框架 Vitest；`test-setup.ts` 连一次性 pg 容器（`TEST_DATABASE_URL`，migrate deploy + vector 扩展）；与生产同引擎。
- 分层：core 纯函数单测 → services 领域单测（含状态机/权限矩阵）→ routes 集成（`app.inject`，含认证头）→ mcp stdio 冒烟。
- 每个 bugfix 必须先写复现用例；用例命名 `描述行为`（中文可），禁止 `test1`。
- 目标：services 行覆盖 ≥80%；routes 核心链路 100% 覆盖。
- `scripts/acceptance.sh` 一键门禁：建库→全测→起服务→curl 冒烟→汇总退出码。

## 9. 日志与可观测

- Fastify logger 默认 info；禁 `console.log` 打业务日志（用 `app.log`；MCP 用 console.error）。
- 日志脱敏：禁打印 token/密码/密钥明文；请求日志默认不含 body。
- 关键路径（登录、密钥操作、上传、MCP 调用）必须落 UsageEvent/audit，日志与审计双轨。

## 10. 代码风格硬指标

- 单文件 ≤ 400 行（routes ≤ 250）；单函数 ≤ 50 行；嵌套 ≤ 3 层。
- 命名：函数动词开头（`createBug`/`resolveProject`）；布尔 `isX/hasX`；常量 SCREAMING_SNAKE。
- 注释只写「为什么」：约束、坑、协议要求；不写「是什么」。
- `strict: true` + `noUncheckedIndexedAccess`；禁 `any`、禁 `as unknown as`（除第三方类型缺陷处须注释）。
- 导入：Node 内置 → 外部 → 内部相对；`.js` 后缀（NodeNext）。

## 11. Git 与 PR 规范

- 同前端：Conventional Commits；PR checklist：
  ```
  - [ ] tsc / vitest 全绿
  - [ ] 新增/修改 migration 可重复执行
  - [ ] 新接口有序列化 + 错误码 + 测试
  - [ ] 无 password_hash/key_hash 泄漏面
  - [ ] 写操作有事件/审计
  - [ ] README/API 摘要同步
  ```

## 12. 部署与运维规范

- 配置全走 env（config.ts 唯一出口）；`.env.example` 永不失真。
- Docker：三阶段构建；健康检查 `/api/health`；数据只落 `/data` 卷；入口自动 `migrate deploy`。
- 备份策略：`pg_dump` 逻辑备份（每日）+ attachments 目录 rsync；命令写入 README，容器内 `docker exec` 执行。
