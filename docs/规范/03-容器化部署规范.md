# VibeHub 容器化部署规范（单容器 · PostgreSQL + pgvector）

> 目标形态：**一条命令起一个容器**，容器内同时运行 PostgreSQL 16/17（含 pgvector 插件）与 VibeHub 应用（API + 静态前端 + MCP SSE 端点）。开源用户 `docker compose up -d` 即可团队可用，无需任何外部依赖。
> 本规范是部署形态的唯一真理源；Dockerfile / docker-compose.yml / README 部署章节均以本规范为准。

---

## 1. 单容器架构

```
┌─────────────────────── vibehub:latest（一个容器）───────────────────────┐
│  supervisord（PID 1，进程守护）                                            │
│   ├─ postgres（pgvector/pgvector:pg17 官方镜像基底内置）                    │
│   │    · 数据目录 /var/lib/postgresql/data（卷 1）                         │
│   │    · 启动时应用 initdb 首初始化；之后直接用既有数据                     │
│   └─ node（VibeHub Server，Fastify）                                       │
│        · REST API + 前端静态页（web/out）+ SSE + MCP SSE 端点 :3210        │
│        · 附件存储 /data（卷 2）                                            │
│  启动序列：postgres 就绪 → CREATE EXTENSION vector → prisma migrate       │
│            deploy → 启动 app（迁移失败即退出，容器重启重试）                 │
└──────────────────────────────────────────────────────────────────────────┘
        ▲ 3210 (HTTP/SSE/MCP-SSE)        ▲ 5432 不对外暴露（仅容器内）
   IDE / 浏览器 / 团队客户端
```

**为什么选 postgres 基底镜像**：pgvector 需编译扩展，`pgvector/pgvector:pg17` 官方镜像预装；在其上装 Node 22 与 supervisord，得到「数据库与应用同容器」的最小形态。

## 2. 镜像构建（Dockerfile 终态契约）

```dockerfile
ARG PG_IMAGE=pgvector/pgvector:pg16      # 必须在首个 FROM 之前声明（FROM 只消费全局作用域 ARG）

# ---------- 阶段 1：server 构建 ----------
FROM node:22-bookworm-slim AS server-builder
WORKDIR /app
COPY package.json package-lock.json ./
COPY server/package.json server/
RUN npm ci --workspace=server --include-workspace-root=false
COPY server/tsconfig.json server/
COPY server/prisma server/prisma
COPY server/src server/src
RUN npx prisma generate --schema=server/prisma/schema.prisma
RUN npm run build -w server

# ---------- 阶段 2：server 生产依赖（精益树：剔 next/vitest/tsx 等开发依赖） ----------
FROM node:22-bookworm-slim AS server-prod
WORKDIR /app
COPY package.json package-lock.json ./
COPY server/package.json server/
RUN npm ci --workspace=server --include-workspace-root=false --omit=dev

# ---------- 阶段 3：web 构建（Next.js 静态导出） ----------
FROM node:22-bookworm-slim AS web-builder
WORKDIR /app
COPY package.json package-lock.json ./
COPY web/package.json web/
RUN npm ci --workspace=web --include-workspace-root=false
COPY web/ web/
RUN npm run build -w web            # output:export → web/out

# ---------- 阶段 4：运行镜像（pgvector 基底 + Node 22 + supervisord） ----------
FROM ${PG_IMAGE} AS runtime
# Node 22 取官方 tarball（apt 源版本不可控）；按 dpkg 架构选 x64/arm64（R54：写死 x64 在 arm64 上 ELF 报错）
RUN set -eux; ARCH="$(dpkg --print-architecture)"; \
    case "$ARCH" in amd64) NODE_ARCH=x64 ;; arm64) NODE_ARCH=arm64 ;; *) exit 1 ;; esac; \
    apt-get update; apt-get install -y --no-install-recommends curl ca-certificates xz-utils supervisor; \
    curl -fsSL "https://nodejs.org/dist/v22.14.0/node-v22.14.0-linux-${NODE_ARCH}.tar.xz" -o /tmp/node.tar.xz; \
    tar -xJf /tmp/node.tar.xz -C /usr/local --strip-components=1; rm /tmp/node.tar.xz; \
    apt-get purge -y xz-utils; apt-get autoremove -y; rm -rf /var/lib/apt/lists/*
WORKDIR /app
COPY --from=server-prod    /app/node_modules ./node_modules
COPY --from=server-builder /app/node_modules/.prisma ./node_modules/.prisma
COPY --from=server-builder /app/server/dist ./dist
COPY --from=server-builder /app/server/prisma ./prisma
COPY --from=web-builder    /app/web/out /app/web/out
COPY skills /app/web/out/skills      # 技能随服务发布：GET /skills/vibehub-mcp/SKILL.md
COPY deploy/supervisord.conf /etc/supervisor/conf.d/vibehub.conf
COPY deploy/entrypoint.sh /usr/local/bin/vibehub-entrypoint.sh
RUN chmod +x /usr/local/bin/vibehub-entrypoint.sh
ENV NODE_ENV=production PORT=3210 HOST=0.0.0.0 DATA_DIR=/data POSTGRES_USER=vibehub POSTGRES_DB=vibehub
EXPOSE 3210
VOLUME ["/var/lib/postgresql/data", "/data"]
HEALTHCHECK --interval=30s --timeout=5s --start-period=25s --retries=3 \
  CMD curl -fsS http://127.0.0.1:3210/api/health || exit 1
ENTRYPOINT ["/usr/local/bin/vibehub-entrypoint.sh"]
```

### supervisord 配置契约

```ini
[supervisord]
nodaemon=true
user=root

[program:postgres]
command=/usr/local/bin/docker-entrypoint.sh postgres
user=postgres
autorestart=true
priority=10
stdout_logfile=/dev/stdout
stdout_logfile_maxbytes=0

[program:vibehub]
command=node /app/dist/bootstrap.js   ; 等 PG → 建 vector 扩展 → migrate deploy → 起 HTTP
directory=/app
autorestart=true
priority=20
environment=PYTHONUNBUFFERED="1"
stdout_logfile=/dev/stdout
stdout_logfile_maxbytes=0
```

### entrypoint.sh 行为契约

```bash
#!/usr/bin/env bash
# 只做两件事：组装 DATABASE_URL → 交权 supervisord。
# 禁忌：PG 由 supervisord 拉起，entrypoint 若在此等 PG 会与 supervisord 顺序倒置而永久等待（R53 实测）。
set -euo pipefail
export DATABASE_URL="postgresql://${POSTGRES_USER:-vibehub}:${POSTGRES_PASSWORD:-vibehub}@127.0.0.1:5432/${POSTGRES_DB:-vibehub}"
exec /usr/bin/supervisord -c /etc/supervisor/supervisord.conf -n
```

> 实现要点（R53 定稿）：「等 PG 就绪 → `CREATE EXTENSION IF NOT EXISTS vector` → `prisma migrate deploy` → 起 HTTP」四步**不在 entrypoint**，而在 `dist/bootstrap.js`（supervisord 的 `vibehub` 程序命令）；entrypoint 只组装 `DATABASE_URL` 并 `exec supervisord`。bootstrap 用 `pg_isready` 最多等 60 秒，未就绪即退出交由 supervisord 重启。

## 3. docker-compose.yml 终态

```yaml
services:
  vibehub:
    build: .
    image: vibehub:latest
    container_name: vibehub
    restart: unless-stopped
    ports:
      - "3210:3210"
    volumes:
      - vibehub-pg:/var/lib/postgresql/data   # 卷名与既有部署一致，改名会挂到空卷   # PostgreSQL 数据
      - vibehub-data:/data                    # 附件 / 派生图 / 回收站
    environment:
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD:?请在 .env 设置}
      POSTGRES_DB: vibehub
      DATABASE_URL: postgresql://vibehub:${POSTGRES_PASSWORD}@127.0.0.1:5432/vibehub?schema=public
      PORT: "3210"
      JWT_SECRET: ${JWT_SECRET:?openssl rand -hex 32 生成}
      REGISTRATION_OPEN: "true"
      ATTACHMENT_TRASH_DAYS: "30"
      EMBEDDING_PROVIDER: ${EMBEDDING_PROVIDER:-none}   # none | dashscope（默认关，§6）
      EMBEDDING_BASE_URL: ${EMBEDDING_BASE_URL:-https://dashscope.aliyuncs.com/compatible-mode/v1}
      EMBEDDING_MODEL: ${EMBEDDING_MODEL:-text-embedding-v3}
      EMBEDDING_DIM: ${EMBEDDING_DIM:-1024}
      EMBEDDING_SEND_DIM: ${EMBEDDING_SEND_DIM:-true}
      EMBEDDING_USE_BASE64: ${EMBEDDING_USE_BASE64:-true}
volumes:
  vibehub-pg:
  vibehub-data:
```

`.env`（随仓库提供 `.env.example`）：`POSTGRES_PASSWORD`、`JWT_SECRET` 必填，缺失即启动失败并打印生成命令。

## 4. 数据卷与备份

| 卷 | 内容 | 备份方式 |
| --- | --- | --- |
| `/var/lib/postgresql/data` | PostgreSQL 数据目录 | `docker exec vibehub pg_dump -U vibehub vibehub > backup.sql`（逻辑备份）；或停容器后整卷拷贝 |
| `/data` | 附件 + 派生图 + 回收站 | rsync/tar 整目录；与 DB 备份**无需严格同时**（附件元数据在库，文件丢了进回收站逻辑兜底） |

恢复：`psql -U vibehub vibehub < backup.sql` + 拷贝 `/data`。升级：拉新镜像 → `compose up -d` → 入口自动 `migrate deploy`（幂等）→ 健康检查变绿即完成。

## 5. 网络与暴露面

- 仅暴露 **3210**：HTTP（API + 前端）+ SSE（`/api/events`）+ MCP SSE（`/mcp/sse`）。
- PostgreSQL **不对宿主机暴露**（容器内 127.0.0.1:5432），杜绝误开库端口。
- 需要外部 TLS 时，官方 documented 方式：前置 Nginx/Caddy（compose profile `proxy`，默认不启用），不在本容器内处理证书。

## 6. pgvector 能力（「有用到向量就用 pg 插件」的落地）

### 6.1 预置

- 镜像基底含 pgvector；entrypoint 执行 `CREATE EXTENSION IF NOT EXISTS vector`——**零成本预置**，不用不收费。

### 6.2 数据模型增量（随步骤 01 落地）

```prisma
/// 语义索引：实体embedding（bug/note），model 记录所用模型，便于重建
model Embedding {
  id         String   @id
  entityType String                 // bug | note
  entityId   String
  model      String                 // 如 text-embedding-3-small / bge-m3
  dim        Int      @default(1536)
  createdAt  DateTime @default(now())
  updatedAt  DateTime @updatedAt
  @@unique([entityType, entityId, model])
  @@index([entityType])
}
```

PostgreSQL 侧 raw SQL 建向量列与索引（Prisma 不原生支持 vector 类型， migration 中以 `$executeRaw` 追加并注释）：

```sql
ALTER TABLE "Embedding" ADD COLUMN "embedding" vector(1536);
CREATE INDEX ON "Embedding" USING hnsw ("embedding" vector_cosine_ops);
```

### 6.3 能力开关（默认关，打开即用）

| 能力 | 触发条件 | 说明 |
| --- | --- | --- |
| 语义搜索（⌘K 混合检索） | `EMBEDDING_PROVIDER != none` + 密钥 | 关键词命中之外补充 top-k 相似缺陷/便签 |
| 重复缺陷提示 | 同上 | 新建缺陷时向量相似度 >0.92 提示「可能重复」并列出候选 |
| 相似便签聚合 | 同上 | 随手记墙按语义聚类展示 |

Provider 规范：`EMBEDDING_PROVIDER=openai-compatible` 时读 `EMBEDDING_BASE_URL/EMBEDDING_MODEL/EMBEDDING_API_KEY`（兼容 OpenAI `/embeddings` 协议，可指向本地 vLLM/Ollama）。**降级策略**：provider 不可用 → 自动回落纯关键词检索，功能不报错（写入时异步入队，失败重试 3 次后放弃并记日志）。

## 7. MCP 在容器化形态下的接入（重要）

容器内的应用不能靠 IDE 拉起了，MCP 走 **SSE 传输 + Bearer 密钥**：

```json
{ "mcpServers": { "vibehub": {
  "url": "http://<服务器IP>:3210/mcp/sse",
  "headers": { "Authorization": "Bearer vhk_live_xxx" }
} } }
```

- `/mcp/sse` 由 Fastify 挂载（复用 `@modelcontextprotocol/sdk` 的 SSEServerTransport），握手时校验 API Key 与 scope，权限模型与 stdio 模式**完全一致**（步骤 03 的 guard 直接复用）。
- 同机部署仍可用 stdio（开发场景）：`docker exec` 或宿主机直接跑 `npm run start:mcp`。
- 步骤 03 的 MCP 文档因此增加「双传输」章节；14 工具契约不变。

## 8. 资源与调优（单机团队默认值）

| 资源 | 最低 | 推荐 |
| --- | --- | --- |
| 内存 | 1GB | 2GB（pg + node 各 ~512MB 空闲） |
| CPU | 1 核 | 2 核 |
| 磁盘 | 5GB | 20GB+（附件增长） |

容器内 PostgreSQL 调优（entrypoint 追加 `postgresql.conf` 片段，小库默认值即可）：`shared_buffers=256MB`、`max_connections=100`、`wal_compression=on`。**不搞花哨调优**——单机团队规模，默认值+向量索引足够。

## 9. 验收清单（Docker 合入前逐项）

- [ ] `docker compose up -d`（空 `.env`）→ 启动失败并提示缺少 POSTGRES_PASSWORD/JWT_SECRET
- [ ] 填好 `.env` → 一次起容器 → `/api/health` 200 → 打开 :3210 是登录页
- [ ] `docker exec vibehub psql -U vibehub -c '\dx'` 显示 **vector** 扩展
- [ ] 注册第一个用户 = Owner；刷新页面数据在
- [ ] `docker compose restart` → 数据仍在（卷生效）
- [ ] `docker exec vibehub pg_dump -U vibehub vibehub | head` 有输出
- [ ] `curl -N localhost:3210/mcp/sse` 无密钥被拒（401/人话错误）；带密钥完成 initialize
- [ ] 镜像内无 root 运行的应用进程？——**例外说明**：postgres 官方镜像以 postgres 用户运行，supervisord 以 root 守护；此为 pg 基底镜像的标准形态，安全边界由「5432 不暴露 + 容器网络隔离」保证
- [ ] 构建体积 ≤ 1.2GB（web/out 内置）
